How to use VisualTalk

Lire en : Français

This guide is written for people, not engineers. If you can copy and paste, you can set up VisualTalk. The whole one-time setup is: get the app, pick a server, paste three values. Everything after that is buttons.

1. Get the app

Desktop (macOS, Windows, Linux): download the installer for your system from the Downloads page. On macOS the first launch may need a right-click → Open (the builds are not notarized yet — the Downloads page explains).

Phones and tablets: the Android app is in closed testing on Google Play and the iOS app is with Apple for review. Until both are public, everything in this guide works exactly the same on desktop.

2. Pick a server (one-time, about five minutes)

VisualTalk does not own any conferencing servers — that is the whole point. Your meetings run on a server you choose. Pick one of the two:

Option A — LiveKit Cloud (free tier, someone else's computer)

Create a free account at cloud.livekit.io, create a project, and open the project's dashboard. It shows three values: a URL (it starts with wss://), an API key and an API secret. Copy all three somewhere handy. You are done with this step.

Option B — your own server (the free bundle, your own computer)

Download the self-hosted server stack zip from the Downloads page, unzip it, and follow the two commands in its README (“Quick start”). Then, in plain words:

  • the address is the server's phone number;
  • the API key is a membership-card number;
  • the API secret is the PIN for that card.

The server creates the card and the PIN by itself on first start and writes them into its own notebook, a file called docker/.env. You never invent them — you copy them. In the bundle folder, this command reads the notebook out loud:

python3 scripts/livekit-local.py creds

It prints the URL, the API key and the API secret, ready to copy. (No commands? Open the docker folder and open .env in any text editor — on a Mac press Cmd+Shift+. in Finder once to reveal hidden files.) Which address to use depends on where the app runs:

The app runs on…Paste this address
The same computer as the serverws://localhost:7880
A phone or tablet on your home Wi-Fiws://<the server computer's Wi-Fi address>:7880, e.g. ws://192.168.1.20:7880. Find it — Mac: System Settings → Wi-Fi → Details… → IP Address; Windows: Settings → Network & Internet → your connection → IPv4 address. Start the server with --host so phones can reach it.
An Android emulator on the server computerws://10.0.2.2:7880

3. Tell the app (one-time)

In VisualTalk, open Settings → LiveKit (the gear icon at the bottom left). Paste the three values into LiveKit Server URL, API Key and API Secret, then press Save Configuration. The app can now dial your server. No account, no cloud sign-up, nothing leaves your home. Treat the API secret like a password: never paste it into chats, screenshots or emails.

4. Your first meeting

  • New Meeting starts one immediately. Copy meeting link gives you a visualtalk.app/j/… page: send it to whoever you invite — it shows the room code with a copy button.
  • Join is for entering a room code or invite link someone sent you.
  • Schedule puts a meeting on a date; it then appears on your dashboard at the chosen time, and invites work the same way.
  • Before entering, the preview shows your camera so you can check your face and background, pick the right microphone and camera, and join muted or camera-off if you prefer.
  • In the meeting, the toolbar controls the microphone, camera and screen share; the side panel holds chat and file sharing with the other participants.
  • Notes on the dashboard is a personal notepad that stays on your device.

5. Recording and captions (optional)

The meeting organizer can record a meeting. With the Docker bundle, recordings land in docker/recordings/ on the server machine and nowhere else; the Recordings tab lists them. If your server runs the optional speech-to-text add-on, live captions appear during meetings (that add-on translates into English only).

6. When it misbehaves (plain-words fixes)

  • A phone spins on “Connecting…” forever → you pasted the “this computer” address. A phone needs the Wi-Fi address from the table in step 2.
  • “Unauthorized” or an auth error → the key or secret was retyped by hand and has a typo. Copy-paste instead; neither value contains spaces.
  • It worked yesterday but not today → the server is asleep. Start it again (with the bundle: python3 scripts/livekit-local.py up).
  • Camera or microphone silent → the operating system asked permission on first use and was declined. Re-allow VisualTalk in your system's privacy settings, then restart the app.
